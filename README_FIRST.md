# “箱”政治模拟器：GitHub收纳版

这个目录专门解决GitHub网页端一次难以上传大量文件的问题。

顶层没有散放全部源码，而是按用途分成少量归档。上传整个 `github_shelf` 时，GitHub看到的只是十来个文件。

## 最简单的使用方式

下载并解压：

```text
00_FULL_PORTABLE_APP.zip
```

它包含完整、可直接运行的项目。其他分类包用于阅读、归档和单独交换某一部分源码。

## 分类

| 文件 | 内容 | 是否可单独运行 |
|---|---|---|
| `00_FULL_PORTABLE_APP.zip` | 完整程序、CLI、数据、情景和文档 | 是 |
| `01_CORE_ENGINE.zip` | 决策、状态、议会、媒体、历史动力等核心代码 | 否，需配合完整包 |
| `02_PERSONAS_AND_DATA.zip` | 人物卡、政党集合体、环境与校准数据 | 否 |
| `03_INSTITUTIONS_AND_LAW.zip` | 基本法检查、制度矩阵、程序状态 | 否 |
| `04_SCENARIO_PACKS.zip` | 内置情景源码，不包含运行报告 | 否 |
| `05_PLUGIN_ARCANA.zip` | 可选ARCANA插件及历史规则 | 否，可装入完整包 |
| `06_DEVELOPER_TESTS.zip` | 单元测试、实验和开发示例 | 否 |
| `07_DOCUMENTATION.zip` | 架构、PSS、媒体、历史动力等说明 | 否 |

## 为什么分类包不能分别运行

它们是“收纳抽屉”，不是相互独立的软件发行版。Python模块之间仍然存在正常依赖。要运行模型，请始终使用完整包；要查找或分享某一类内容，再打开对应抽屉。

## GitHub上传建议

如果只想让别人下载使用，上传：

```text
README_FIRST.md
00_FULL_PORTABLE_APP.zip
```

如果还希望别人按模块下载源码，再上传其余七个分类包。这样不需要一次拖入一百多个文件。
